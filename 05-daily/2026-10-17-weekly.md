## What repeated

**A command's output was redirected away and hid a real failure, reported as success instead.** This
is now on record in three separate documents, three unrelated tools:

- `04-reference/shell-differences-that-produce-wrong-output.md:76-78` — stderr redirected away hid
  `error: you must specify two arguments` from a quoting bug.
- `01-install/cka-practice-cluster-and-checks-that-lie.md:503-505` — the same quoting bug against
  `kubectl auth can-i`, invisible for the same reason.
- `01-install/proxmox-on-ec2-bare-metal.md:253` and `:358-359` — `qm snapshot … >/dev/null 2>&1`
  swallowed `snapshot feature is not available`, and the script reported a plausible `2006 ms` timing
  for a command that had done nothing. This is this week's new occurrence.

Three documents converging on one cause is a structural pattern, not three unrelated mistakes: a
script that discards a command's output cannot distinguish a slow success from a fast failure, and a
timing number is not evidence that anything ran. No existing reference document states this as a
standalone rule — it currently lives only inside the three incident write-ups.
