## What repeated

**① The false-healthy-status pattern is no longer occasional — it is the dominant shape of this
week's findings, and it is still not written down as a standing rule.** Last week's review named it
after three documents and suggested "a single reference note... rather than waiting for a fourth
instance." A fourth instance did not arrive — six did, in one week:
[[cka-workloads-scheduling-drills]] (`READY 3/3` over a stuck rollout, a DaemonSet reporting
`DESIRED/READY 2/2` on a three-node cluster with every column agreeing, `--ignore-daemonsets` leaving
a pod "Running" on a drained node), [[cka-services-ingress-storage-drills]] (a Service with no
endpoints, an Ingress with an address and a `1/1` controller returning nothing, a `Bound` PVC with the
data on a different node, CoreDNS `2/2 Running` with clean logs while it no longer answers cluster
names), [[cka-practice-cluster-and-checks-that-lie]] (`get nodes` / `/healthz` / `etcd 1/1` all
passing regardless of whether an etcd restore actually loaded anything, a `NotReady` node's pod still
reading `Running`, `kubectl get nodes` VERSION reading stale after a correct control-plane upgrade),
[[valkey-redis-dragonfly-on-kubernetes]] (`PING` → `PONG` and a populated Service endpoint while every
write is refused), [[pulumi-kubernetes-outputs-and-drift]] (`pulumi preview` reporting `5 unchanged`
against a cluster with the Deployment already deleted), and [[chrome-devtools-protocol-testing]] (two
coverage APIs reporting 0% unused code on a page that is mostly dead). Every one of these documents
cross-links at least one of the others for this exact shape — the pairwise citation habit flagged last
week continues — but the pattern itself still has no home. It is now the single most-repeated finding
in the whole repository and there is still no [[04-reference]] page titled anything like "a status
field is not the property it describes."

**② The same shell-quoting failure hit twice more, and this time it was captured as a reference
document instead of only as a footnote.** [[shell-differences-that-produce-wrong-output]], written
this week, exists specifically because zsh's non-splitting of unquoted expansions broke
[[cka-practice-cluster-and-checks-that-lie]] twice, a dash `${@:2}` failure hit inside a container in
[[cka-workloads-scheduling-drills]], and a missing `timeout` binary produced a false finding in the
same CKA page. This is last week's ① pattern playing out correctly for once: a repeated cause got
promoted to a reference page in the same week it repeated for the third and fourth time, rather than
being left as a pairwise link. [[powershell-objects-and-the-checks-that-lie]] is the direct sequel,
written the same day to cover the object-pipeline version of the same class of trap.
