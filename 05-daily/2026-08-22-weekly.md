## What the week left behind

Twenty-five documents this week, the busiest window so far: 18 in `01-install/`, 3 in `02-runbook/`,
2 in `04-reference/`, and 2 in `05-daily/`. Two build-outs account for almost all of it. One is an
on-prem data platform — Garage replacing MinIO as the S3 endpoint, plus Trino, Spark-on-k8s,
CloudNativePG, Airflow, and Kafka/Strimzi — cross-linked densely enough that reading any one of
[[garage-object-storage-onprem]], [[trino-query-engine-onprem]], [[spark-on-k8s-onprem]],
[[postgresql-cnpg-onprem]], or [[airflow-orchestration-onprem]] surfaces the other four. The other is
a Python AI-agent-tooling set — [[langgraph-control-flow]], [[markitdown-document-to-markdown]],
[[smolagents-code-agents]], [[litellm-streamlit-chat]], [[pydantic-ai-structured-output]],
[[dspy-prompt-optimization]] — with the same dense cross-linking. Alongside those,
[[terraform-remote-backend-lock-import]] and [[terraform-state-operations]] closed the
import/remote-locking gaps in Terraform state handling, [[gitlab-ci-argocd-fastapi-procedure]]
extracted a runnable procedure out of the existing GitLab CI → Argo CD narrative, and
[[bruno-api-client]] gave the repo its first API-client reference.

This was a build week, not a verification week: most of the new install guides carry a `verified`
date the day they were written, but several ship with a named, honestly-disclosed gap rather than a
clean pass (see below).

## What repeated

**① The same quota exhaustion blocked three separate documents.** [[smolagents-code-agents]],
[[dspy-prompt-optimization]], and [[pydantic-ai-structured-output]] each hit the Gemini free-tier
request quota partway through verification and each ships an incomplete run as a result — a live
agent run with no recorded final answer, a compiled-vs-baseline accuracy table left blank, and a
notebook with empty output cells. All three carry an identical-shaped follow-up, and by coincidence
of when each was written, all three are dated 📅 2026-08-22 — due the day this review runs. This is a
capacity problem for the AI-tooling cluster, not three unrelated incidents: anything else added to
this cluster on the same API key should expect the same wall.

**② The rootless-podman-on-kind block on `iscsid` surfaced again.** [[garage-object-storage-onprem]]
and [[s3-object-storage-options]] both record the same cause blocking a live Longhorn-backupstore
test this week — `iscsid` will not start under rootless podman, so the property cannot be proven on
`kind`. This is the same obstacle [[longhorn-storage-onprem]] recorded on 2026-08-07; three documents
now carry it, and none has a workaround.
