## What repeated

**The sandbox's permission classifier refusing to execute a freshly-downloaded, unsigned binary hit
two of this week's three runs independently, each worked around a different way.**
[[2026-08-12-cosign-sbom-signing]] tried `install.sh`-fetched `syft` — denied even after `chmod +x` —
and fell back to running `syft` and `cosign` from their official container images instead.
[[2026-08-10-argo-rollouts-canary]] hit the same wall trying to install the `kubectl-argo-rollouts`
CLI plugin, and worked around it by skipping the plugin entirely and driving the `Rollout` CRD with
plain `kubectl patch`/`get -o jsonpath`. Same cause, two documents, two different workarounds in the
same week — and it is also the reason all three documents got stuck as `not-executed` back in August
in the first place (that earlier blocker was `docker run`/`kind create cluster` sitting behind an
unanswerable approval prompt, not a binary-execution refusal, but the family of problem — the sandbox
denying a specific class of command with no user to approve it — is the same one). Worth stating once
in [[topics]] or a reference document instead of re-discovering a variant of it per lab.

**A guess made from documentation alone, once actually run, turned out wrong — twice.**
[[2026-08-12-cosign-sbom-signing]]'s original draft predicted the `spdx`/`spdxjson` predicate-type
mismatch would surface at `verify-attestation`; running it this week showed the failure actually
happens earlier, at `attest`, with a different error (`invalid attestation: decoding json`), and no
attestation is ever written. [[2026-08-11-prometheus-3-13-lts]]'s draft predicted the missing-flag
error would read `"unknown function with name \"max_of\""`; the actual Prometheus 3.13.0 response is
`"function \"max_of\" is not enabled"` — a different string, important if anyone scripts a check
against it. Both are exactly the CLAUDE.md "prefer a check you have watched fail" principle paying
off: the unproven checks were marked as guesses, not fact, and this week's run is what separated the
one that held ([[2026-08-11-prometheus-3-13-lts]]'s build-version check) from the two that didn't.
