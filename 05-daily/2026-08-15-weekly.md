runbook, or troubleshooting document was added or verified this week. The one non-daily change in

So this was a week of research notes, not hands-on verification — and each of the six says so itself.

puts `docker run`, `kind create cluster`, and `kubectl apply` behind an approval prompt that has no
user to answer it. That is the week's real finding, not any one topic.

None of these are wrong commands — each is copied from official docs or built from a confirmed
version/flag, and each document says plainly that nobody has watched it run. But six documents in a
row with no `verified` date and no executed check is a capacity problem, not six separate incidents:
the daily-topic skill, run on schedule, currently cannot produce a verified document by construction.
It only ever produces a follow-up that reads "run the lab above end to end."

**② Those follow-ups are starting to slip before anyone gets to them.** See Follow-ups below — two of
the six "run it for real" tasks this pattern created are already past their own due date, one day
after being written.
