## What repeated

**① The "a check reads a stand-in for the property" pattern — named as the week's dominant finding in
both the 2026-08-08 and 2026-09-05 reviews, and asked for as a dedicated reference page in the last
review's "Next week" — repeated again this week without that page getting written.**
[[fastapi-seven-ways-a-200-lies]] is built entirely around this shape: a swallowed exception, a missing
auth dependency, and a health check that keeps returning `200` with the database gone are all a status
code standing in for a property it doesn't verify — and the document explicitly cross-links
[[valkey-redis-dragonfly-on-kubernetes]] and [[container-image-size-and-what-breaks]] as the same
shape elsewhere. [[container-image-size-and-what-breaks]] independently hits it: `/healthz` passes on
the 8.37 MB image that cannot make an HTTPS call or read a timezone, both silently, and the document's
own follow-up names the gap ("check whether the readiness probe can be made to catch the broken
image"). [[flink-event-time-windows-and-late-data]]'s section 8 is a milder instance — a recovery
control that passed but was confounded by the sink's commit protocol, so it measured the wrong thing
rather than the one it claimed to. [[linux-the-name-is-not-the-thing]] sits adjacent rather than inside
this pattern: it generalizes to "a name is not the thing" at the kernel level (a path, a permission bit,
a PID) and links to [[container-image-size-and-what-breaks]] and [[cka-workloads-scheduling-drills]] as
related, but it does not consolidate the specific status-field claim the last two reviews asked for.
The count is now at least nine documents across three consecutive weekly windows with the pattern named
and no reference page under it.
